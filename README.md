# Plain Talk

让 Codex 用直白、自然、方便扫读的表达方式把事情说清楚。按你提问的顺序回答，必要信息一次给全，少用书面套话，减少来回追问。

通过插件安装并启用后自动加载，不用每次输入触发词或手动调用 Skill。

## 适合解决什么问题

- **回答太书面，看完还得翻译一下**：用日常说法解释具体发生了什么，少用抽象词和套话。
- **问了两件事，先答后面的或者只答后面的**：按提问顺序回答，把每个问题说清楚。
- **只说“改对应逻辑”，还得追问改哪里**：把查到的文件、位置和具体改法直接给出。
- **为了简短省掉必要信息**：保留原因、操作方法和重要影响，删掉重复解释。

简单问题几句话说完，复杂问题把关键关系讲清楚。

## 回答会变成什么样

### 少说抽象话，直接说发生了什么

#### 不够直白

> 当前问题是由于对象生命周期与异步操作之间存在不一致导致的。

#### Plain Talk

> 对象已经销毁了，但之前启动的异步任务还没结束。回调回来后又访问了这个对象，所以报错。
>
> 问题不在对象池，而在异步任务没有跟着对象一起结束。

### 简洁，但不靠省略关键信息

#### 偏简洁的 Skill

> 把排行榜的显示数量改成 20 即可。

#### Plain Talk

> `RankPanel.cs` 第 86 行把显示数量限制成了 10：
>
> ```csharp
> int displayCount = Mathf.Min(rankList.Count, 10);
> ```
>
> 把这里的 `10` 改成 `20` 就行。
>
> 数据已经取到了前 50 名，不用改请求和排序逻辑。

## 安装

在终端中依次运行：

```sh
codex plugin marketplace add DullSword/plain-talk
codex plugin add plain-talk@plain-talk
```

也可以将这两条命令发给 Codex，让它代为安装。

## 插件启用

1. 在 Codex 的插件管理中启用 **Plain Talk**。
2. 按提示审核并信任 Plain Talk 的自动加载操作。
3. 新建编码任务，直接描述需求。

## 插件自动加载时机

新建或恢复任务时自动加载。清空或压缩对话上下文后会重新加载；Codex 分配给子代理的任务也会加载相同规则。

## 停用

在插件管理中关闭 **Plain Talk**，并新建任务继续工作。
